# L-BFGS-B 3.0 reference-fixture provenance

These fixtures are oracle data generated by the authoritative Fortran
L-BFGS-B 3.0 release. The Fortran is used only by the opt-in regeneration
script; it is not vendored, compiled by Cargo, or linked into
`ariadne-lbfgsb`.

## Upstream source

- Project page:
  <http://users.iems.northwestern.edu/~nocedal/lbfgsb.html>
- Distribution:
  <http://users.iems.northwestern.edu/~nocedal/Software/Lbfgsb.3.0.tar.gz>
- Distribution SHA-256:
  `f5b9a1c8c30ff6bcc8df9b5d5738145f4cbe4c7eadec629220e808dcf0e54720`
- Upstream identification: L-BFGS-B 3.0, March 2011; the project page says
  the distribution was last changed August 2, 2011.
- Files compiled from the verified archive: `lbfgsb.f`, `linpack.f`,
  `blas.f`, and `timer.f`.

The archive and project page identify the release as New/Modified BSD
(BSD-3-Clause). See the crate's `THIRD_PARTY_NOTICES.md`.

## Generation environment

The committed files were generated on Windows x86-64 with:

```text
GNU Fortran (x86_64-posix-seh-rev0, Built by MinGW-Builds project) 15.2.0
```

Compiler flags:

```text
-O0 -std=legacy -ffixed-line-length-none -ffree-line-length-none -fno-fast-math
```

Run from the repository root:

```powershell
& .\crates\lbfgsb\tests\reference\regenerate.ps1
```

The script downloads the release into a temporary directory, verifies the
archive hash before extracting, compiles the upstream routines with
`trace_generator.f90`, and generates all fixtures in temporary storage. It
canonicalizes them to UTF-8 without a BOM and LF line endings, validates the
complete file set and CSV headers, then replaces the committed corpus with
rollback backups. Temporary source and binaries are always removed.
Regeneration requires PowerShell, `tar`, network access, and `gfortran`;
ordinary `cargo test` does not.

## Cases and objective definitions

`driver1.csv` exactly uses official driver1's setup: `n=25`, `m=5`,
`factr=1e7`, `pgtol=1e-5`, `x_i=3`, odd variables bounded `[1,100]`, and even
variables bounded `[-100,100]`.

`driver2.csv` exactly uses official driver2's setup and custom stopping rules:
`n=25`, `m=5`, `factr=pgtol=0`; stop at 99 evaluations or when
`|proj g| <= 1e-10(1+|f|)`.

Both official cases use the extended Rosenbrock function:

```text
f(x) = 4 * (0.25 * (x_1 - 1)^2 + sum(i=2..n, (x_i - x_(i-1)^2)^2))
```

and the analytic gradient copied from the corresponding official drivers.

`driver3-large-n.csv` uses official driver3's `n=1000`, `m=10`, bounds,
starting point, objective, gradient, and evaluation/projected-gradient stopping
rules. It deliberately removes the wall-clock stop, making this a deterministic
large-n driver3 variant.

`edge-mixed-bounds.csv` is an independent (non-upstream) quadratic fixture:

```text
f(x) = sum(i=1..4, (x_i - [1,2,-2,3]_i)^2)
```

Its infeasible start `[-3,9,7,-8]` combines boxed, unbounded, and lower-only
variables and independently records initial projection behavior.

`audit-mixed-rollover.csv` is an independent diagonal-quadratic driver run
through the unmodified upstream `setulb`. Its eight variables include
two-sided, lower-only, upper-only, unbounded, and fixed bounds. The infeasible
start projects variables 1, 3, and 5 before `FG_START`. Variables 6, 7, and 8
are constructed so their first generalized-Cauchy breakpoints are all exactly
`t=1`, exercising the official heap's strict tie comparisons. The fixture uses
`m=2` and completes eight accepted iterations, forcing compact-history ring
rollover while retaining full accepted vectors.

`dcsrch-cases.csv` calls the official upstream `dcsrch` directly and records
its deterministic convergence, `STPMIN`, and `STPMAX` terminal cases. The Rust
line-search unit test consumes these values as an independent subroutine-level
oracle.

The reverse-communication interface exposes accepted iterates and aggregate
counters, but not internal decisions such as the positive-directional-
derivative correction inside `subsm`, the rounding/interval-tolerance
`dcsrch` warnings, the operands on the exact curvature-skip threshold, or the
specific compact factorization that triggered a history refresh. The
configured Rust `maxls` rollback is also API policy rather than a Fortran
trajectory state. Those paths are therefore covered by focused Rust invariant
tests rather than represented as falsely independent trajectory fixtures.

Every accepted iteration records the iteration number, cumulative function/
gradient evaluation count, objective, and projected-gradient infinity norm.
Driver1, driver2, and the edge case record full `x` and `g` vectors at every
accepted iteration. To keep the large-n fixture practical, driver3 records
full vectors only at the initial and terminal states. Floating-point values use
17 digits after the decimal point in scientific notation.

Hashes cover the exact committed UTF-8 bytes with canonical LF line endings.
The integrity test recomputes these values, so checkout settings cannot silently
change the corpus.

Exact low-order bits can vary with compiler, architecture, or floating-point
contraction choices. The hashes identify the committed gfortran 15.2.0
reference corpus; future parity tests should use explicit numeric tolerances
rather than requiring byte equality across toolchains.
